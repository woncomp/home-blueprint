# 移除断路器左右切换，改为双端子同时生效

> 创建日期：2026-10-25  
> 类型：修改计划，不包含实现代码  
> 范围：强电箱断路器端子、线路归属、墙面 2D 连线、右侧强电箱面板、JSON 数据迁移与测试

## 1. 目标

移除“每个断路器只能选择左侧或右侧出线”的概念，改为：

- 每个断路器固定拥有**左、右两个独立端子**。
- 两个端子始终同时存在、同时可用，不再存在“活动侧 / 非活动侧”。
- 左、右端子可以分别连接不同电线，也可以只使用其中一侧。
- 无论从哪一侧接出，所有下游电线和节点都归入**同一个断路器、同一条线路、同一种颜色**。
- 如果两侧线路在箱外再次连通，仍只计为同一条线路，电线和节点不得重复统计。
- 删除右侧强电箱面板中的“左 / 右”切换按钮，以及所有持久化的 `br.side` 状态。

这里的“左 / 右”只表示端子在箱体上的固定物理位置，不再表示可切换的出线方向。

## 2. 非目标

本次不调整：

- 强电箱尺寸、断路器行高和端子高度的计算规则。
- 断路器数量、顺序、命名、颜色分配和线路高亮方式。
- 普通设备、电线、穿墙连通、墙段和 3D 走线的既有行为。
- 不同断路器之间发生异常连通时的处理策略；该问题另行定义，不在本次顺带修改。

## 3. 当前实现与问题

当前每个断路器只有一个真实端子节点：

```js
{ id, label, terminal, side }
```

相关行为如下：

1. `js/panel.js` 通过“左 / 右”按钮修改 `br.side`。
2. `js/main.js` 的 `syncTerminals()` 根据 `br.side` 把同一个端子移到箱体左侧或右侧。
3. `js/wallface.js` 虽然画出左右两个圆点，但二者共用 `br.terminal`；只有活动侧可以连线，点击另一侧只是切换状态。
4. `js/model.js` 的 `computeCircuits()` 只从 `br.terminal` 的一个连通分量收集线路。

因此，现有模型无法让同一断路器的两侧同时保留不同接线，必须升级为两个真实端子。

## 4. 目标数据模型

### 4.1 断路器结构

将数据结构升级为版本 3，每个断路器使用两个端子引用：

```js
{
  id: 'b1',
  label: '插座-客厅',
  terminals: {
    left: 't1-left',
    right: 't1-right'
  }
}
```

约束：

- `terminals.left` 和 `terminals.right` 都必须是真实存在、且 `type === 'terminal'` 的节点 ID。
- 两个 ID 必须不同。
- 每个端子节点只归属于一个断路器，不允许被多个断路器或两侧重复引用。
- 新数据中不再写入 `terminal` 或 `side`。
- 左、右端子仍跟随所属断路器使用同一行高度；横向位置分别固定在箱体左右边缘内缩 1 cm 处。
- 端子继续不可单独删除、不可拖动，仍随强电箱的墙面、面、位置和高度同步。

### 4.2 为什么保留两个真实节点

左右端子必须分别拥有节点 ID，才能：

- 让 `wires.from / wires.to` 精确记录电线接在哪一侧。
- 复用现有连线、删除电线、跨墙走线和 3D 渲染逻辑。
- 在切换箱体位置或墙长变化时分别同步两侧坐标。
- 在不增加虚拟电线的前提下，把两侧下游组件归入同一断路器。

## 5. 旧数据迁移

在 `normalizeData()` 中增加 v1 / v2 → v3 的断路器端子迁移，并将默认数据升级到版本 3。

### 5.1 迁移顺序

1. 保留现有顶层 `breakerBox` 并入 `nodes` 的兼容逻辑。
2. 完成现有 v1 节点 `pos` 从米数到 0～1 归一化坐标的转换。
3. 在坐标已经归一化后，迁移每个断路器的端子结构，避免新建端子被重复转换。
4. 将 `data.version` 设为 `3`，再进入 `validateData()`。

同时把 `createEmptyData()` 创建的新数据版本改为 3，避免空户型仍沿旧版本路径解析。

### 5.2 单端子迁移规则

对旧断路器 `{ terminal, side }`：

- 当 `side === 'right'` 时，原 `terminal` 作为 `terminals.right`，新建左端子。
- 其他情况（包括 `side` 缺失）按旧默认行为处理：原 `terminal` 作为 `terminals.left`，新建右端子。
- 保留原端子节点 ID 和所有既有电线引用，不改写 `wires`。
- 新端子使用新的全局唯一 ID，继承箱体的 `wall / face`，初始 `pos / height` 可取箱体值，随后由 `syncTerminals()` 统一计算。
- 删除迁移后的 `terminal` 和 `side` 字段。

如果旧断路器缺少 `terminal`，则直接新建左右两个端子；原来允许“未接线断路器”的兼容能力不变。

### 5.3 校验规则

- `validateData()` 接受迁移后的版本 3。
- 对版本 3 严格要求每个断路器都有完整的 `terminals.left / terminals.right`。
- 校验引用存在、节点类型为 `terminal`、左右 ID 不同、端子归属唯一。
- 旧字段只应在 v1 / v2 迁移输入中出现，版本 3 导出结果不得再包含它们。
- 迁移失败或校验失败时，继续沿用现有“整体不应用、保留原文”的 JSON 弹窗行为。

## 6. 线路计算修改

修改 `js/model.js` 的 `computeCircuits()`：

1. 对每个断路器读取左右两个端子。
2. 分别找到两个端子在 `wires + links` 并查集中的连通根节点，组成 `roots` 集合。
3. 收集任一端位于这些连通分量中的电线，写入该断路器的 `wireIds / nodeIds / wallIds`。
4. 更新 `wireCircuit / nodeCircuit / wallsWithCircuit` 的方式保持不变。
5. 使用 `Set` 去重；两侧同属一个连通分量时，每根电线仍只处理一次。

关键约束：**不要为了归并线路而对左右端子额外执行 `union()`**。双端子是同一断路器的两个入口，但数据中不应凭空增加一条箱内电线或改变现有连通拓扑；这里只把两个入口对应的连通分量归入同一线路。

预期结果：

- 仅左侧接线：与旧行为一致。
- 仅右侧接线：与旧行为一致。
- 两侧分别接两条不相连的支路：两条支路都属于该断路器，颜色一致，面板段数为两者之和。
- 两侧支路在箱外连通：仍是一条线路，不重复计数。
- 两侧都未接线：该断路器保持空线路。

## 7. 端子创建与同步

### 7.1 新增断路器

修改 `js/main.js` 的 `addBreaker` 事件：

- 一次创建左右两个 `terminal` 节点。
- 将二者写入 `terminals.left / terminals.right`。
- 不再创建单一 `terminal`，也不再写入 `side`。
- 调用现有刷新流程，由 `syncTerminals()` 设置实际坐标。

可将“为断路器创建双端子”提取为模型层辅助函数，供新增断路器和旧数据迁移复用，避免两套 ID、标签和节点结构逻辑逐渐不一致。

### 7.2 同步坐标

修改 `syncTerminals()`：

- 遍历每个断路器的左右两个端子。
- 对左端子使用固定负偏移，对右端子使用固定正偏移。
- 两个端子使用相同的 `breakerTerminalHeight(i, n, box.height)`。
- 保留墙长边界裁剪、箱体移动和墙面切换时的同步行为。

`breakerTerminalPosDelta(side)` 可以保留为纯几何函数，但其参数只来自固定的左右位置，不再读取任何断路器状态；相关注释和测试名称需改为“双端子位置”，避免继续表达“方向切换”。

## 8. 界面与交互修改

### 8.1 右侧强电箱面板

修改 `js/panel.js` 和 `css/style.css`：

- 删除每个断路器后的“左 / 右”按钮及其点击事件。
- 删除不再使用的 `.breaker-side-btn` 样式。
- 保留名称编辑、线路颜色、段数统计和点击高亮。
- 段数直接读取合并后的 `circuit.wireIds.size`，无需在面板中分别计算左右两侧。

### 8.2 墙面 2D 展开

修改 `js/wallface.js` 的强电箱绘制：

- 每个断路器仍只占一行，左右各绘制一个端子。
- 两个端子均使用所属线路颜色的实心圆点，不再绘制“非活动侧”的空心状态。
- 左圆点绑定 `br.terminals.left`，右圆点绑定 `br.terminals.right`。
- 删除 `data-side`、`active` 判断和点击另一侧切换 `br.side` 的分支。
- 两侧都直接调用 `onNodeMouseDown(e, terminalId)`，复用现有选择、连线、跨墙连线和查看模式行为。
- 保留 A / B 面现有水平显示变换，确保端子与真实节点坐标一致。
- 端子仍不可通过删除工具单独删除，也不可拖动。

### 8.3 3D 与其他视图

`js/scene3d.js` 当前不直接绘制箱内端子，电线位置又来源于端子节点，因此原则上无需结构性修改。实现后应回归验证：

- 左右两侧电线均从正确的箱体边缘出发。
- 两侧线路颜色和高亮一致。
- 移动强电箱或修改墙长后，两侧电线同步跟随。
- 户型 2D 顶视图不出现额外可选端子或异常标记。

## 10. 测试计划

### 10.1 自动化测试

调整或新增以下测试：

1. **双端子几何**（替换 `tests/breaker-terminal-side.test.mjs` 的切换语义）
   - 左右偏移一负一正且关于中心对称。
   - 两侧均内缩 1 cm。
   - 同一断路器左右端子高度相同。
   - 不再测试 `side` 缺省值或切换行为。

2. **线路计算**
   - 仅左、仅右接线均能识别线路。
   - 左右分别连接两个不相连支路时，两条支路归入同一个 `breakerId`。
   - 两侧支路在箱外连通时，电线、节点和段数不重复。
   - 同一断路器两侧线路使用相同颜色，点击高亮覆盖两侧。
   - 多个断路器的独立线路仍正确区分。

3. **JSON 迁移与校验**（更新 `tests/json-persistence.test.mjs`）
   - v2 默认左侧数据：保留原端子为左侧并新增右端子。
   - v2 `side: 'right'` 数据：保留原端子为右侧并新增左端子。
   - 原电线 ID、起终点和其他实体不变。
   - 缺失旧 `terminal` 时自动补双端子。
   - v1 顶层强电箱数据先完成坐标迁移，再正确生成双端子。
   - v3 缺失端子、引用不存在、引用非 terminal 节点、左右重复或跨断路器重复引用时被拒绝。
   - 导出后的版本 3 数据不含旧 `terminal / side` 字段。

4. **既有测试数据**
   - 更新 `tests/wall-segments.test.mjs` 等测试中的断路器夹具为双端子结构。
   - 保留墙段归属、持久化和其他既有断言，确认本次修改没有引入无关回归。

### 10.2 浏览器手工验收

1. 打开默认布局，确认右侧强电箱面板不再出现“左 / 右”按钮。
2. 进入强电箱所在墙面的 2D 展开，确认每个断路器左右各有一个实心端子。
3. 从同一断路器左侧连接一个插座，再从右侧连接另一个插座。
4. 确认两条支路颜色相同，右侧面板显示为一个断路器，段数为两侧合计。
5. 点击该断路器，确认 3D 同时高亮两侧线路。
6. 删除其中一侧电线，确认另一侧线路和归属不受影响。
7. 新增断路器，确认无需任何切换即可直接从两侧分别连线。
8. 移动强电箱、调整所在墙长度，确认左右端子和电线一起跟随。
9. 分别导入旧版左侧、旧版右侧和缺少端子的 JSON，确认原有接线保留且另一侧可立即使用。
10. 查看并保存 JSON，确认版本为 3，双端子结构完整，无 `side` 或旧 `terminal` 字段。
