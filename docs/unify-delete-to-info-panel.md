# 电路编辑删除入口统一收敛到信息面板

> 创建日期：2026-10-26
> 类型：修改计划，不包含实现代码
> 范围：顶部工具栏、墙面展开 2D 工具栏与信息面板、3D 信息面板、删除守卫逻辑、README 与手工验收

## 1. 目标

电路编辑模式（2D 与 3D 均如此）下，删除电气对象（节点、电线、穿墙连通）统一只能从**信息面板**发起：

- 移除顶部工具栏常驻的「删除选中」按钮（`#btn-delete-entity`）。
- 移除墙面展开 2D 工具栏中的「✕ 删除」工具（`data-wftool="remove"`）。
- 3D 中通过右侧信息面板的「删除节点 / 删除电线」按钮删除（已有能力，保留）。
- 2D 墙面展开中，选中节点或电线后，在展开视图右侧的信息面板（`#wallface-info`）中删除——该面板目前只有属性编辑，**需要新增删除按钮**。
- 所有既有删除守卫（只读邻墙、强电箱保护、端子保护、级联清理）保持不变，只是入口收敛。

## 2. 非目标

本次不调整：

- 户型编辑（plan 模式）的删除方式：`Delete` 键删除墙/门、信息面板的「删除墙 / 删除门」按钮均保留。
- 2D 墙面展开中 `Delete` 键删除选中门的快捷键（`js/wallface.js` 顶部键盘监听）保留——门不属于电气节点。
- 各类删除的守卫规则、级联清理范围和数据持久化格式。
- 选择、连线、放置等其他 2D/3D 交互行为。

## 3. 当前实现与问题

目前删除电气对象有三个入口，行为不一致：

1. **顶部工具栏「删除选中」**：`index.html` 中 `#edit-tools` 内的常驻按钮，仅在电路编辑模式显示。`js/main.js` 的 `refreshToolbar()` 根据选中类型（node/wire/door）控制可用态，点击后走 `deleteSelectedEntity()` 分发删除。
2. **2D「删除」工具**：墙面展开工具栏中的 `remove` 工具。激活后点击节点、电线、穿墙连通线分别触发 `wallface.deleteNode()`、`wallface.deleteWire()`、`removeLink()`。这是**穿墙连通唯一的删除入口**。
3. **信息面板**：3D 右侧 `js/panel.js` 按选中类型渲染「删除电线 / 删除节点」按钮（门、墙同理），是本次唯一保留的入口。

问题：

- 2D 与 3D 的删除入口不一致，2D 靠工具态、3D 靠面板按钮，用户需要在两套心智模型间切换。
- 「删除选中」与信息面板按钮功能重复。
- 收敛后若只删工具不提供替代，穿墙连通将完全无法删除，2D 中节点/电线也将失去删除入口。

## 4. 修改内容

### 4.1 移除顶部工具栏「删除选中」

- `index.html`：删除 `#btn-delete-entity` 按钮；`#edit-tools` 容器保留（仍承载 `edit-hint` 提示文字）。
- `js/main.js`：
  - 删除 `btn-delete-entity` 的点击监听与 `deleteSelectedEntity()` 函数（移除按钮后无其他调用方）。
  - `refreshToolbar()` 删除针对删除按钮的可用态逻辑，仅保留 `edit-hint` 刷新；`setMode()` 中对 `#edit-tools` 的显隐控制不变。
- 能力兜底：编辑模式下选中门后，信息面板的「删除门」按钮仍存在，门的删除能力不丢失；墙只在户型编辑中可选中，不受影响。

### 4.2 移除 2D「删除」工具

- `index.html`：删除 `data-wftool="remove"` 按钮。
- `js/wallface.js`：
  - `onNodeMouseDown()` 中 `tool === 'remove'` 分支：删除节点直接改为走选择路径（与 `select` 工具一致地选中并联动右侧信息面板）。
  - 电线命中处理中 `tool === 'remove'` 分支：删除电线改为与 `select` 一致地选中电线（`selectedWireId` + `onSelect` + `renderInfo()`）。
  - 连通线命中处理中 `tool === 'remove'` 分支：删除后改为选中相关节点，连通线本身不再直接响应点击删除。
  - `renderInfo()` 的 `toolHints` 删除 `remove` 条目。
  - `deleteNode()` / `deleteWire()` 方法**保留**（含守卫），供 4.3 新增的面板按钮复用。
- 工具栏默认工具仍为 `select`，`setTool()` 无需结构性改动。

### 4.3 2D 信息面板新增删除入口

修改 `js/wallface.js` 的 `renderInfo()`：

- **选中节点**：在现有属性（沿墙位置、离地高度、说明、连接电线数）下方新增「删除节点」按钮。
  - 复用 `this.deleteNode(node.id)`，保留其内部守卫（邻墙只读提示、强电箱保护、级联清理电线与连通）。
  - 按钮仅在该节点位于当前活动墙（非 `readOnly`）时可用；只读节点不渲染按钮，与现有输入框禁用规则一致。
- **选中电线**：在现有说明编辑下方新增「删除电线」按钮，复用 `this.deleteWire(wire.id)`。
- **穿墙连通**：选中节点时，把现有的「连接电线：n 段」扩展为连通列表——每处连通（`data.links` 中涉及该节点的记录）显示对方节点描述并附单个删除按钮，调用 `removeLink()` 后 `changed()`。
  - 这是移除 `remove` 工具后连通线的唯一删除入口，必须补齐。
  - 只读节点同样不渲染删除按钮。
- 按钮样式复用 `tool-btn danger`（与 3D 面板一致），追加到 `css/style.css` 中如需调整间距。

### 4.4 3D 信息面板

`js/panel.js` 现有「删除电线 / 删除节点」按钮及 `deleteWire / deleteNode` 事件链路（`main.js:187-195`）保持不变。节点分支中「连通：n 处连通」为只读统计，本次不扩展（3D 场景不绘制连通线，2D 中删除即可）。

### 4.5 文档

- `README.md`：更新操作说明——电路编辑模式下删除节点/电线/连通统一在右侧信息面板操作，删除工具与「删除选中」按钮的描述一并删除；保留户型编辑与门快捷键的说明。

## 5. 回归点与守卫核对

实现时逐项确认以下既有行为未被削弱：

- `js/main.js` `deleteNodeById()`：墙面展开期间仅允许删除当前活动墙段、端子不能单独删除、强电箱不能删除、级联清理 `wires/links`、删除后清除全局选中。
- `js/wallface.js` `deleteNode()`：邻墙只读提示与强电箱保护保留。
- 删除电线后 `selectedWireId` / 全局 `wire` 选中正确清空。
- 删除节点或电线后线路重算、颜色与高亮正常刷新（现有 `changed()` → `onChange` 链路不变）。
- 移除 `remove` 工具后，不存在任何残留路径引用 `tool === 'remove'`（全局搜索确认）。

## 6. 测试计划

### 6.1 自动化测试

### 6.2 浏览器手工验收

1. 进入电路编辑模式：顶部工具栏不再出现「删除选中」，只剩模式切换与提示文字。
2. 3D 中选中插座/端点 → 信息面板「删除节点」删除成功，相关电线与连通被级联清理。
3. 3D 中选中电线 → 信息面板「删除电线」删除成功。
4. 打开墙面展开 2D：工具栏不再出现「✕ 删除」，默认即为「☝ 选择」。
5. 2D 中点击节点/电线只执行选中（不再直接删除），右侧信息面板出现对应详情与删除按钮。
6. 2D 中通过信息面板删除当前墙节点/电线成功；切换到相邻墙只读节点，面板无删除按钮，输入框禁用。
7. 选中带穿墙连通的节点，信息面板列出每处连通并可逐条删除。
8. 尝试删除强电箱及端子：按钮不存在或点击被守卫拦截，提示信息符合预期。
9. 删除后线路颜色、面板段数、点击高亮均正确刷新。
10. 户型编辑模式回归：`Delete` 键与信息面板删除墙/门不受影响；README 描述与实际行为一致。

- 删除任意电气对象后，线路计算、颜色、统计与高亮即时正确刷新。
- 户型编辑的墙/门删除能力与 2D 门的 `Delete` 快捷键不受影响。
- 完整自动化测试通过，浏览器手工验收全部通过。
