# 相邻墙面计算：问题定位与拓扑修复指南

> 调查日期：2026-10-25  
> 范围：2D 三墙展开中的左右邻墙、连续“设为当前墙”跳转，以及这些结果对跨墙连线的影响。  
> 本文是调查与修复指南，不包含代码修复；默认布局 JSON 无需修改或迁移。

## 1. 结论摘要

默认布局中的房间检测结果是正确的，2D 的 A 面反向显示规则也是正确的。错误集中在 `js/model.js` 的 `adjacentWallViews`：

1. 在墙段切点调用 `segOfNode`，把“节点应归入哪一段”的规则误用于“边界两侧有哪些墙段”，导致候选段选错。
2. 当前可见房间也按边界点重新求取；当边界是当前段的 `t1` 时，可能取得下一段的房间，而不是当前视图内沿的房间。
3. 房间不匹配后仍执行几何选面回退，把已经失败的空间连续性判断变成一个看似合法、实际属于另一房间或外侧的结果。
4. 先按 `turn` 和墙 ID 选出唯一候选墙，再检查房间；T/X 接点处的候选墙、候选段没有一起参与房间连续性筛选。
5. 邻墙返回的是细粒度“逻辑墙段”，而 3D 拾取使用“面范围段”。同一面、同一房间的连续墙段因此会在跳转时被意外截断。

推荐修法不是继续增加局部特判，而是把邻墙定义为**同一平面拓扑面（通常是一个房间或外侧）的有向边界环上的前驱和后继**。`detectRooms` 已经进行了半边面遍历，应复用这套拓扑关系，而不是在 2D 展开时重新猜一遍邻接关系。

## 2. 当前调用链与两种“段”

3D 点击墙面后的调用链为：

```text
scene3d.pick
  └─ faceSegOf(...)                  按被点击的面求面范围段
      └─ main.js: wallface.open(...)
          └─ wallface.computeViews()
              └─ adjacentWallViews(...)  计算左右邻墙
```

需要区分两个概念：

| 概念 | 来源 | 用途 |
| --- | --- | --- |
| 逻辑墙段 | `buildWallSegments` | 保存整墙上两侧房间归属发生变化的区间，含 `left/right` |
| 面范围段 | `faceSegOf` | 将同一侧、同一房间的连续逻辑段合并，决定一次 2D 展开显示多大范围 |

例如，一堵墙的 A 侧依次属于房间 R1、R2，而 B 侧始终是房间 R3：

- 逻辑墙段应有两段，因为完整 `(left, right)` 发生变化；
- A 面应有两个面范围段；
- B 面应只有一个整墙面范围段，不应在 T 型接点处中断。

目前 `scene3d.pick` 已使用面范围段，但 `adjacentWallViews` 仍通过 `segOfNode` 返回逻辑墙段，两个接口的范围语义不一致。

## 3. 默认布局复现

### 3.1 相关几何和房间归属

当前墙 `wmvnptk6r_2`：

```text
start = (1.8, 2.3551219847144145)
end   = (1.8, 3.7)
A 面 = 客厅
B 面 = 卧室A
```

它的 A 面在显示时反向展开，因此显示左边界是 `end = (1.8, 3.7)`，该点接 `w3`。

`w3` 从 `(9, 3.7)` 指向 `(0, 3.7)`，在 `x = 1.8` 处约为 `t = 0.8`：

| 逻辑段 | 沿墙范围 | A 面侧 | B 面侧 |
| --- | --- | --- | --- |
| `w3#0`，标题“段 1” | `[0, 0.8)` | 外侧 | 客厅 |
| `w3#1`，标题“段 2” | `[0.8, 1]` | 外侧 | 卧室A |

所以当前墙 `wmvnptk6r_2 · A 面` 的左邻必须是：

```text
墙 w3 · B 面 · 段 1
```

实际结果却是：

```text
墙 w3 · A 面 · 段 2
```

### 3.2 错误发生的准确过程

`adjacentWallViews` 当前按以下顺序执行：

1. 用边界点找到 `w3`，得到 `tc ≈ 0.8`。
2. 调用 `segOfNode(w3Segments, tc)`。
3. `segOfNode` 的既定规则是半开区间 `[t0, t1)`，切点归右侧段，于是返回 `w3#1`（卧室A侧段）。
4. 当前房间是客厅，而 `w3#1` 的 B 侧是卧室A，房间匹配失败。
5. `pickNeighborFace` 没有因匹配失败停止，而是进入几何回退。
6. 当前左边界的前进方向朝向 `+z`；`w3` 的 A 面法线也是 `+z`，得分高于 B 面，于是错误选择 A 面。

因此，A/B 错误是后续几何回退造成的，段 2 错误则发生在更早的切点归属阶段。仅修改法线得分无法根治。

### 3.3 连续跳转同样失效

从 `wmvnptk6r_2 / A / 段 1` 连续向左跳转，现有结果会经过外侧面和其他房间，随后进入一个不包含起点的循环，而不是绕客厅边界后回到起点。

即使手工从正确的 `w3 / B / 段 1` 开始，现有链路也会在 `w1` 的客厅侧只选择逻辑段 3，随后在 T 型接点跳去其他墙，仍然无法形成客厅闭环。这证明问题不是单一 A/B 判断，也不是单一浮点误差。

修复前完整测试基线为 `node --test tests/*.test.mjs`：99 项全部通过。现有邻墙测试只有简单矩形和基础 T 型场景，没有覆盖“切点两侧房间不同”“面范围合并”和“连续跳转闭环”。

## 4. 正确模型：沿同一有向面边界取前驱/后继

### 4.1 把一次墙面展开看作有向半边

定义一个视图引用：

```js
{
  wallId,
  face,                 // 0 = A，1 = B
  range: { index, t0, t1 },
  faceId,               // 拓扑面 ID；房间和外侧都应有
  roomKey               // 可为 null，仅用于命名/展示，不代替 faceId
}
```

对任意墙面，显示坐标的左到右方向定义为：

- B 面：原墙 `start → end`；
- A 面：原墙 `end → start`。

按这个方向观察时，当前可见面始终位于有向边的右侧。于是：

- 显示右边界：取该有向边所属右侧面的 `next`；
- 显示左边界：取该有向边所属右侧面的 `prev`；
- 邻墙的 A/B 面由返回有向边与原墙方向是否一致直接确定，不再需要 `pickNeighborFace` 猜测。

对于合并后的面范围段，只在整个范围的显示首端取 `prev`、显示末端取 `next`。范围内部被合并的 T 型原子边不应触发跳转。

### 4.2 直接复用 `detectRooms` 的面遍历

`detectRooms` 已具备所需的大部分信息：

- 墙被交点切成原子边 `edgeInfos`；
- 每个顶点的关联边已按角度排序；
- 每条有向半边所属的面已记录在 `halfFace`；
- 面遍历本身就是在计算同一边界环上的下一条边。

建议在遍历阶段额外输出稳定的拓扑导航数据，例如：

```js
halfEdges: [{
  id,
  wallId,
  t0,
  t1,
  from,
  to,
  faceId,       // 此有向半边左侧的面
  nextId,
  prevId
}]
```

随后为每条原子墙边的两个方向建立索引：

```text
(wallId, 原子段 t0/t1, A/B) → 显示方向有向半边
```

当前显示半边的可见面在右侧；若直接复用 `halfFace`（记录左侧面），可以统一取原半边的反向半边，避免在邻墙函数中重复推导角度规则。

若需要手工实现角度关系，在现有升序 `atan2` 排序下：

- 左侧面的后继：在终点从“指回起点”的射线起，取逆时针下一条，即现有 `(j + 1) % n`；
- 右侧面的后继：取相反方向的一条，即 `(j - 1 + n) % n`；
- 更稳妥的做法仍是遍历一次后同时保存 `next/prev`，不要在 `adjacentWallViews` 再写一套角度算法。

### 4.3 面范围段必须显式物化

建议新增与 `faceSegOf` 共用逻辑的 `buildFaceRanges(logicalSegments, face)`：

```js
[{
  id,
  wallId,
  face,
  index,
  t0,
  t1,
  faceId,
  roomKey
}]
```

`faceSegOf` 可以保留为“按位置查面范围”的兼容包装，但邻墙导航不应再通过切点位置反查段。

原子边映射到面范围时，应使用**区间包含/重叠关系**：

```text
range.t0 - EPS <= edge.t0
且
range.t1 + EPS >= edge.t1
```

不要调用 `segOfNode(boundaryT)`，也不要用边界中点碰运气。导航关系已经给出了唯一的原子边，接下来只需找到包含它的范围。

## 5. 推荐修复步骤

### 第一步：统一当前视图的房间和范围

在 `adjacentWallViews` 开始时，将传入的 `seg` 归一化为面范围段：

- 若传入 `null`，使用整墙范围；
- 若传入范围快照，按该面、该范围内部的位置找到对应面范围；
- 当前房间/面 ID 从该范围读取，不要在 `leftT/rightT` 上重新调用 `segOfNode`。

这样可以保证同一次展开的左右边界始终使用同一个可见面。

### 第二步：让 `detectRooms` 输出边界导航

在现有半边面遍历中保存每条有向半边的 `next`，遍历完成后反向建立 `prev`。同时保留有效 `faceId`：

- 房间面与外侧面的拓扑身份应分开；
- 不要用 `roomKey == null` 代表“所有这些都是同一个面”；
- 被过滤的微面、无有效面的开放墙应标记为不可进行面边界导航。

现有房间多边形、`segRooms` 和房间命名逻辑可以保持不变。

### 第三步：用前驱/后继重写 `adjacentWallViews`

推荐的内部流程：

```js
function adjacentWallViews(context, currentRef) {
  const current = normalizeFaceRange(context, currentRef);
  const firstDisplayEdge = displayEdgeAtRangeStart(current);
  const lastDisplayEdge = displayEdgeAtRangeEnd(current);

  return {
    left: toFaceRangeRef(prevOnVisibleFace(firstDisplayEdge)),
    right: toFaceRangeRef(nextOnVisibleFace(lastDisplayEdge)),
  };
}
```

`toFaceRangeRef` 同时确定：

- `wallId`：来自目标原子边；
- `face`：目标显示方向与原墙方向相同为 B，相反为 A；
- `range`：包含目标原子边的整个面范围段；
- `faceId/roomKey`：必须仍属于当前可见面。

不再使用以下信息决定封闭房间内的邻墙：

- `turn` 最大；
- 墙 ID 大小；
- 法线与 `towardDir` 的点积最大；
- 切点上的 `segOfNode`。

### 第四步：限制几何回退的使用范围

开放墙、孤立墙、退化或非法拓扑仍可保留几何回退，但必须满足：

1. 只有当前视图一开始就没有可导航的有效面时才进入回退；
2. 封闭房间的前驱/后继查找失败时返回 `null` 并输出诊断，不得静默改选另一个面；
3. 回退结果明确是 best-effort，不承诺房间闭环；
4. 若必须对开放几何排序，应使用接点射线的角度连续性，而不是“转弯越大越好”和 ID 次序。

这条限制很关键：本例正是“房间匹配失败后继续几何回退”把错误掩盖成了合法标题。

### 第五步：保持 UI 和持久化格式不变

`wallface.computeViews`、`activateView` 可以继续消费 `{wallId, face, seg}` 形状，只需确保 `seg` 现在始终是面范围段快照。

无需修改：

- `wallface.js` 中 A 面反向、B 面正向的显示规则；
- `leftT/rightT` 所表达的显示左右概念（最终拓扑实现会直接使用前驱/后继）；
- `wallFaceCorner` 的面线交点算法；
- 节点、门、墙的持久化 JSON；
- `segOfNode` 对节点“切点归右侧段”的既有规则。

特别不要为了让本例通过而全局修改 `segOfNode`：那只会把同类问题转移到另一侧，并破坏节点归属测试。

### 仅做紧急止血时的最小改动

若暂时不能引入半边导航，至少应同时做以下三项，而不是只改 A/B 得分：

1. 当前房间从当前面范围内部读取，不从 `tEnd` 读取。
2. 在接点处枚举所有相交的 `(候选墙, 候选逻辑段)`，先筛选可见侧房间等于当前房间的项，再决定候选墙和面；匹配失败不得几何回退。
3. 选中候选逻辑段后，用该段内部的 `t` 调用 `faceSegOf`，返回合并后的面范围，而不是直接返回候选逻辑段。

这种写法可以修复本例，但仍是在局部重建拓扑；对于复杂 T/X 接点、候选次序和闭环保证，仍应完成上述前驱/后继方案。

## 6. 必须满足的验收不变量

对任意有效面范围视图 `v`：

### 6.1 同一面边界

邻墙与当前墙必须属于同一个 `faceId`。对于封闭房间，房间 key 也必须相同；不能从客厅跳到卧室或外侧后再继续成链。

### 6.2 左右互逆

```js
const left = adjacent(v).left;
const right = adjacent(v).right;

sameView(adjacent(left).right, v) === true;
sameView(adjacent(right).left, v) === true;
```

比较时必须包含 `wallId + face + range.t0/t1`，不能只比较墙 ID。

### 6.3 闭环

从封闭房间的任一墙面出发，持续向同一方向跳转：

- 必须在有限步内回到完全相同的起始视图；
- 在回到起点前不应重复其他视图；
- 环上每一步都属于同一个房间；
- 向左走出的环与向右走出的环互为反向。

遍历时仍应设置最大步数，例如“有效面范围总数 + 1”，防止非法数据导致死循环。

### 6.4 面范围连续

如果同一原始墙的同一面在 T 型接点两侧仍是同一房间，邻墙返回的必须是合并后的整个面范围，而不是某个逻辑子段。

## 7. 回归测试清单

建议在 `tests/wall-adjacency.test.mjs` 增加以下测试，并读取真实 `data/default.json` 做至少一个端到端模型测试。

1. **默认布局精确回归**  
   `wmvnptk6r_2 / A` 的左邻为 `w3 / B / 段 1`，其范围约为 `[0, 0.8]`；明确断言不是 A 面、不是段 2。

2. **默认布局客厅闭环**  
   从 `wmvnptk6r_2 / A` 连续向左，应依次经过以下视图并回到起点：

   ```text
   wmvnptk6r_2 / A
   → w3 / B / 段 1
   → w2 / B
   → w1 / B（客厅侧连续面范围）
   → w4 / B（客厅侧面范围）
   → wmvnptgj9_1 / A
   → wmvnptk6r_2 / A
   ```

   共 6 个不同的视图；`w1` 不应只返回逻辑段 3。

3. **反向闭环与互逆**  
   对上述每一对邻接视图验证 `left.right === current`、`right.left === current`，再从同一起点向右验证反向闭环。

4. **当前段终点不串房间**  
   当前面范围终止于房间变化切点时，左右两次查询仍都使用当前面范围的房间，不得在 `t1` 取下一段房间。

5. **T 型宿主墙合并**  
   宿主墙被拆成两个逻辑段，但某一侧房间不变时，该侧邻墙结果覆盖整面；跨过内部 T 型接点时不跳走。

6. **T/X 接点候选消歧**  
   多条墙同时接近一个接点时，结果由同一面边界的前驱/后继决定；改变墙 ID 或数组顺序不应改变结果。

7. **开放与孤立墙回退**  
   保留现有孤立墙无邻居、开放几何安全返回的测试；封闭房间查找失败不得进入几何回退。

8. **既有功能回归**  
   继续验证三墙坐标映射、当前墙切换、邻墙只读、跨墙电线校验及 3D 公共角点走线。

## 8. 不建议采用的“修复”

- 只把本例的几何选面从 A 改成 B：段仍会错，其他朝向也会错。
- 给 `tc` 加一个固定正负偏移：A/B 面、左右端和墙方向变化后需要不同符号，本质仍是端点猜测。
- 把 `segOfNode` 改为切点归左：会破坏节点归属，并把问题镜像到另一个方向。
- 房间匹配失败后继续选“得分最高”的面：会再次把不同房间接成一条链。
- 只比较左右墙 ID 是否形成循环：同一堵墙可能有多个面和多个面范围，必须比较完整视图引用。
- 在 `wallface.js` 对标题或左右面板做交换：只会掩盖模型错误，还会影响跨墙连线和 3D 走线。

## 9. 可快速定位问题的诊断信息

开发模式下，建议邻墙计算失败时输出：

```text
current = wallId/face/range/faceId/roomKey
boundary = left/right, point, atomicEdgeId
expected = current visible faceId
actual = candidate wallId/face/range/faceId/roomKey
fallbackUsed = true/false
```

默认布局本例应清楚显示：期望客厅面，旧实现却先命中 `w3#1` 的卧室A侧，再通过 `fallbackUsed = true` 选择外侧 A 面。这样以后可以直接定位拓扑断裂位置，而不必从 UI 标题反推。
